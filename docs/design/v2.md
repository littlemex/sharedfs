# Design v2: one share per path, PVCs as the claim, prepared directories

Supersedes `subpath-proposal.md` after three reviews (security, upstream maintainer, LLM platform user). v1alpha1 is unpublished, so the API changes freely.

## Decisions

| # | Decision | Why | Review |
|---|---|---|---|
| D1 | A `FilesystemShare` is one path on one file system (`spec.path`, immutable, `{namespace}` allowed as a whole segment). Several shares may point at the same source PV | Tenant manifests become identical across teams; no grant composition; the share list is the catalogue (datasets, models, checkpoints) | LLM A, security A2 |
| D2 | Tenants claim with a plain PVC: `storageClassName: <share>-rw` or `<share>-ro`. The controller is the external provisioner of those StorageClasses. `FilesystemShareClaim` is removed | Works with Helm `storageClassName`, StatefulSet volumeClaimTemplates, generic ephemeral volumes, Trainer/JobSet templates; a future in-driver mode is a StorageClass swap | upstream 4 |
| D3 | The controller owns one StorageClass per access level present in the grants: `provisioner: sharedfs.littlemex.github.io`, `reclaimPolicy: Delete`, `allowVolumeExpansion: false`, `volumeBindingMode: Immediate`, `mountOptions` with `ro` for the read-only class | Read-only enforced by mount option (M2/M3); expansion refused by the API server (M14 holds for dynamic PVCs because the class disallows it); Delete removes only the PV object, since our PVs are `provisioned-by` sharedfs and the FSx csi-provisioner ignores them | upstream 4, 2 |
| D4 | A PVC is provisioned only if a single grant of that share selects its namespace and allows the class's access. Otherwise it stays Pending with an Event (`NotGranted`) | Single-grant match; nothing to compose | security A1, A2 |
| D5 | `spec.path` is required; the root is `"/"`. Validation is one pure function used by CEL, the controller and the preparer: relative, `[A-Za-z0-9._-]` segments, no `.`/`..`, no segment starting with `.` or `-`, segment <= 255 bytes, <= 32 segments, <= 1024 bytes, anchored | Fail-closed; no flag injection; no `.lustre` | security A3, A4, C2 |
| D6 | PV for a PVC: name `sfs-<pvc uid>`, CSI copied from the source with the driver's sub-path strategy (Lustre: `mountname/<expanded path>`), own volumeHandle, `claimRef` with uid (ordinary dynamic binding), `persistentVolumeReclaimPolicy: Delete`, mount options: source options minus rw/ro, plus `nosuid,nodev`, plus `ro` for read-only; for read-only `flock` becomes `localflock` | Normal dynamic provisioning removes the Released trap and the bind wait; nosuid/nodev neuter planted binaries/devices; localflock stops a reader from taking cluster-wide locks | security D, F |
| D7 | Drivers without a sub-path strategy (OpenZFS) accept only `path: "/"` | M13 | — |
| D8 | Overlap guard: on the same file system (driver + dnsname + mountname), a share whose path is an ancestor of another share's path may not grant ReadWrite. Such shares get `Ready=False (OverlappingShare)` | An ancestor RW holder can rename a team's directory and plant files (pickle checkpoints) | security A5 |
| D9 | A share with a path other than `"/"` requires its source PV to be bound or reserved (claimRef); otherwise `Ready=False (SourceUnreserved)` | An unreserved source can be bound by anyone, bypassing everything | security A5 |
| D10 | Directory preparation only when `spec.provision` is set (`gid`, `mode`, optional `uid`, default uid 0). Existence is otherwise left to the mount (M10) | Admin pre-creation stays the default; fewer privileged moving parts | security Q2, upstream 6 |
| D11 | Preparer: a Pod (not a Job, to avoid Kueue suspension) in the controller namespace, per (share, expanded path), started only after a PVC from that namespace is granted. Dedicated ServiceAccount, no token, non-root except `CAP_CHOWN`/`CAP_FOWNER` (drop ALL), no privilege escalation, read-only root FS, RuntimeDefault seccomp. Mounts only the parent directory of the target through an internal PV (`nosuid,nodev,noexec`). Input by flags `--name=`; output by termination message JSON; the controller decides from the JSON, not the exit code | Least privilege; no API access from the pod that holds a root-ish mount | security C1, C2, LLM F |
| D12 | Crash-safe create: verify each existing component with `openat(O_NOFOLLOW|O_DIRECTORY)` + `fstat` (parents must be root-owned and not group/other writable, else `InsecureParent`); create the leaf as `.sharedfs-tmp-<random>`, `fchown`/`fchmod` through the fd, then `renameat` to the final name (fails if it exists, then re-verify as existing). Never modifies an existing directory | No root:root leftovers, no TOCTOU chown of someone else's directory | security C3 |
| D13 | Results are kept per (share, namespace) in `FilesystemShare.status.directories[]` with the namespace UID that triggered creation. A PVC from a namespace with the same name but another UID is not provisioned (`NamespaceRecreated`) until an admin removes the entry by annotating the share | Recreated namespaces do not inherit another team's data silently | security A6, LLM E |
| D14 | Revocation: when a provisioned PVC's namespace loses its grant, the deadline is stored on the PV (admin-only object, annotation), and after the grace period and a live re-read the PVC is deleted. Pods keep mounts until they stop | Tenants cannot postpone it by editing their PVC | v1 + security G |
| D15 | Orphan sweep: PVs provisioned by sharedfs whose PVC no longer exists and that are not Released (deleted out of band) are deleted; Released ones are deleted as normal reclaim | Same role as v1 |
| D16 | Not in this version: deeper-than-share paths, per-PVC directories, csi-driver-nfs, project quotas (planned next: needs Lustre 2.15 and `lfs` in the preparer image), EFS | Scope | all |

## Threat model (README)

The boundary is the mount: a PVC from sharedfs mounts only its share's directory. It is not isolation against privileged pods, hostPath, a permissive Pod Security level (`CAP_DAC_READ_SEARCH` and FID tricks, inline volumes), or someone who can create PVs. uid/gid/mode are not a boundary when tenants choose `runAsUser` or when root squash is off. Readers trust writers of the same path (a RW holder of `models` can plant code). Tenant namespaces should run at Pod Security `baseline` or stricter; the controller namespace is `baseline` and holds nothing else.

## Upstream track

A separate patch to aws-fsx-csi-driver: an explicit sub-path volume attribute in NodePublishVolume (validated, backward compatible), documentation for static provisioning of sub-directories, and e2e for M9-M12. sharedfs then uses that attribute when the driver supports it.
